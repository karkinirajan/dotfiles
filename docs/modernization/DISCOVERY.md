## 1. What the repo is

A personal dotfiles and workstation-profile repo for one CachyOS (Arch) machine, written as a book: numbered parts (`01-system` to `07-networking`), each with a README as introduction and one subfolder per chapter. It contains:

- Live config for the desktop (Hyprland, Noctalia, SDDM preset, fontconfig), terminal (zsh, bash, kitty, alacritty, starship, fzf), editors (VS Code, Zed, Sublime), Claude Code (global `CLAUDE.md`, `settings.json`, 10 agents, 2 commands, 25 skills) and local LLM serving (Ollama drop-ins, helper, benchmark harness).
- Root-owned system files kept as plain files for manual install (systemd units, pacman hook, nftables, dnsmasq, NetworkManager, nginx, MariaDB).
- Package manifests (`01-system/cachyos/packages/*.txt`, `06-tools/focus/packages.txt`).
- Runbooks: `README.md` (install), `fresh-setup.md` (agent playbook), `system-summary.md` (host snapshot dated 2026-10-28), `01-system/cachyos/setup.md` (1927-line catalog), `dev-stack.md`.

Users and consumption:

| Consumer | How |
|---|---|
| The owner (Nirajan Karki) | Clones to `~/dotfiles`, runs `install.sh` to symlink or seed files per `manifest.conf`, reads the docs as a reference |
| Claude Code on the owner's machine | `~/.claude/{CLAUDE.md,settings.json,agents,skills,commands}` are symlinks into `05-ai/claude-code/`, so skill and agent content is executed as prompt input every session |
| A future AI agent doing a fresh install | Reads `fresh-setup.md` and the chapter READMEs |
| GitHub readers | Rendered Markdown only |

How it is consumed: **cloned and executed** (`install.sh`, scripts, systemd units, pacman, hyprctl), **read** (docs), and **loaded as prompts** (skills, agents, CLAUDE.md). It is not rendered as a site and has no build step.

## 4. Existing conventions

- **Structure:** `NN-part/` folders, `README.md` per part and per chapter, lowercase kebab-case names except program-required files. Declared in `README.md` section "Conventions" and in the repo `CLAUDE.md` standing instruction: "files and folders properly named and subdivided like a book curriculum and table of contents". This is the curriculum rule's trigger: the numbered book layout stays.
- **Wiring:** `manifest.conf` rows `<link|seed> <repo path> <live path>`. 32 entries, all checked by `install.sh status`.
- **Package lists:** one name per line, `(AUR)` suffix marks AUR packages (inconsistent spacing: one or two spaces; the awk parser handles both). Lists are the declared source of truth for installs.
- **Link style:** relative Markdown links; `README.md` ends with a license. Frontmatter exists only in skills and agents.
- **Dates:** inline "checked on 2026-10-06" style notes in `RESOURCES.md`, "Verified versions (2026-10-12)" in the frontend skills, dated changelog bullets in `focus/README.md`. No machine-readable version file.
- **Tooling:** none. No lint, no CI, no link checking.
- **Commit identity:** recent commits are by `karkinirajan`; two emails appear in history (`karkinirajan1999@gmail.com` and `kneeraazon@gmail.com`).
- **Embedded policy:** `05-ai/claude-code/CLAUDE.md` forbids any AI attribution in commits and forbids the assistant from running `git push/pull/fetch` or `sudo` on the owner's machine. `fresh-setup.md` contains owner-checkpoint prose ("stop for explicit owner input before ..."). Both are the owner's own content and are preserved; see `DECISIONS.md` D-04 and D-05 for how this session treats them.

## 6. Internal inconsistencies

1. **Duplicated topic:** `frontend-expert` (22 reference files + appendices, rev 2, archived) and `frontend-master` (47 files, rev 3) carry the same standards; the former is explicitly superseded. `frontend-master/SKILL.md` says its `references/` are generated from `FRONTEND-MASTER.md` by `scripts/build_kit.py`; neither exists in the repo, so the "do not edit by hand" rule has no regeneration path.
2. **Version skew between files:**
   - `05-ai/ollama/claude-code-bench/ollama-claude-setup.md` names kernel 7.2.6, Ollama 0.34.3, Claude Code 2.1.280; `system-summary.md` says 7.3.0-4, 0.40.11, 2.1.311.
   - `frontend-*` pin pnpm 12.11.2; `system-summary.md` has 12.15.0.
   - `frontend-*` pin Node 24 and say "Node 26 enters LTS on 2026-10-28"; `system-summary.md` runs system Node 26.12.1 and NVM 24.22.1; `setup.md` line 667 still says the CachyOS repo requires `nodejs-25`.
   - `system-summary.md` lists TypeScript 7 globally while the frontend skills forbid installing TypeScript 7 as `typescript`.
   - Hyprland: README says the Lua dispatcher API applies "in 0.55 and newer"; hyprland.conf comment says 0.56.2-x; the Arch repo is already at 0.57.0 (queried 2026-10-28).
   - `setup.md` pins `pytorch-triton-rocm>=3.5.1` (twice, lines 339 and 1826) and Elasticsearch 8.17.0 (twice).
3. **Package lists vs reality (from `packages-inventory.csv`):** 143 explicitly installed packages are in no list (mostly CachyOS base, firmware, filesystem tools, and dev apps like `antigravity*`, `fastfetch`, `yay`, `openssh`, `sudo`, `upwork`); 48 listed packages are absent from the explicit snapshot (mostly installed as dependencies; `noctalia` is listed in `desktop.txt` yet the snapshot shows `noctalia-greeter` and `cachyos-hypr-noctalia` only, so the real package name must be verified). `neofetch` and `docker-machine` appear in the snapshot and are deprecated upstream (to be verified). `netctl` is installed beside NetworkManager.

5. **Hardcoded user paths:** `06-tools/focus` scripts, systemd units and README hardcode `/home/kneeraazon/...`.
6. **Machine-specific identifiers in docs:** the username `kneeraazon` appears in `system-summary.md`; no passwords, IPs or UUIDs found. A scan of the tree for IPv4 addresses found only loopback, RFC 5737 documentation addresses, public DNS resolvers (1.1.1.1, 9.9.9.9, 8.8.8.8) and package versions. No tokens found.
